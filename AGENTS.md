# Заметки для агента

- Две части: MCP-сервер `src/mcp_1c_local_bridge/` (Python, FastMCP из пакета `mcp` 1.x - 2.x переименовал
  FastMCP, поэтому `mcp<2`) и обработка `epf/` (XML-выгрузка; собранный файл - `dist/MCPLocalBridge.epf`).
  Протокол между ними - `docs/protocol.md`: меняешь поля команды или ответа - меняй обе стороны и документ.
- Проверка MCP-стороны: `uv run pytest` (имитация обработки в потоке, `tests/test_bridge.py`).
- Сборка обработки: `scripts/build-epf.ps1 -Server <сервер> -Ref <база>` в Windows PowerShell; исходники скрипт
  сам копирует на локальный диск. Сборка не проверяет синтаксис модулей - он виден только при открытии
  обработки в 1С. Доступность методов в контексте (тонкий клиент, сервер) сверять со справкой платформы:
  `ТекущаяУниверсальнаяДата()` и `ПолучитьСообщенияПользователю()` на клиенте недоступны.
- Обработка должна работать в режиме совместимости 8.3.14: без `Асинх`/`Ждать`, WebSocket и методов новее.
  Обработчик ожидания с интервалом меньше секунды - только однократный, его переподключают после опроса.
- Модули `.bsl` - UTF-8 с BOM и CRLF, пустые строки внутри блоков - с табами отступа блока. Инструменты правки
  нередко срезают эти табы и меняют переводы строк: после правки проверить и вернуть.
- Каталог обмена по умолчанию - `%TEMP%\mcp-1c-local-bridge` у обеих сторон. Свой задаётся на форме обработки
  (`ХранилищеОбщихНастроек`, `MCPLocalBridge`/`КаталогОбмена`) и в `MCP_1C_BRIDGE_DIR` у MCP: автоматически
  стороны его не согласуют. В корне MCP трогает только папки с именем сеанса (8 hex): корень может быть общим.
- Версия - в четырёх местах: `pyproject.toml`, `src/mcp_1c_local_bridge/__init__.py` и `bridgeVersion` в
  `СведенияСеанса()` обеих форм - управляемой и обычной (`epf/ordinary-form/Module.bsl`); формы с `pyproject.toml`
  сверяет тест.
- Управляемая форма - одно поле HTML на встроенном WebKit 1С (`V8WebKit`, проверено на 8.3.27): страницу целиком строит
  `ТекстСтраницы()` только при открытии, дальше блоки и строки журнала меняют её функции JavaScript (`setBlock`,
  `addEntry`, `updateEntry`), вызываемые через `Элементы.ПанельHTML.Документ.defaultView`; если вызов не удался -
  страница перерисовывается целиком. Действия - ссылки `#act:<действие>`, их разбирает `ПанельHTMLПриНажатии`.
  Раскрытые строки журнала и прокрутку форма запоминает на каждом опросе (`pageState`, `СверитьСтраницу`) и выводит
  при полной перерисовке; если на странице строк меньше, чем в журнале (поле HTML загрузило прежний текст),
  страница рисуется заново.
- Серверный `eval`/`execute` - `ДополнитьОтветВыполнением` модуля объекта: без записи транзакция с откатом, запись
  (`allowWrite` и разрешение на форме) - транзакция с фиксацией, только если код отработал без ошибок и не оставил
  своих незавершённых транзакций (`ИтогФиксацииЗаписи`); `transaction=false` - без транзакции. Итог - поле ответа
  `transaction` (`rolledBack`, `committed`, `none`), MCP показывает его в подвале ответа. После ошибки записи,
  которую код перехватил сам, транзакция сломана: `ЗафиксироватьТранзакцию()` не бросает исключение, а молча
  откатывает её (проверено на 8.3.27, сервер и толстый клиент). Поэтому перед фиксацией - пробный запрос: в
  сломанной транзакции он падает («В данной транзакции уже происходили ошибки!»).
- Представления ссылок обработка получает пакетно (`ЗагрузитьПредставления`): `Строка(Ссылка)` без кэша - запрос
  к базе на каждую ссылку, 3000 ссылок - около 10 с.
- Индекс метаданных (`index`): строит модуль объекта (`СведенияИндекса`, `ПорцияИндекса`, `СохранитьИндекс`), порциями
  по бюджету времени из обработчика ожидания формы (`ПродолжитьИндексацию`); хранится в `ХранилищеОбщихНастроек`
  (`MCPLocalBridge`/`ИндексМетаданных`). Меняешь состав или формат индекса - подними `ФорматИндекса()` (он в отпечатке,
  сохранённые индексы перестроятся) и поправь `metaindex.py` и протокол. Свойства объектов метаданных читаются
  напрямую по набору из `СвойстваКоллекции()`: отсутствующее свойство - исключение, объект попадёт в индекс с `error`.
- Обычное приложение: у обработки есть обычная форма `ФормаОбычная` (дополнительная форма, `AuxiliaryForm`), её
  открывает толстый клиент обычного приложения. Это свой интерфейс моста: надписи, кнопки, флажки, табличное поле
  журнала и поле подробностей создаются кодом в `ПередОткрытием`. Движок - опрос, команды, подтверждение, каталог
  обмена, индекс - перенесён из модуля управляемой формы, вызовы сервера заменены вызовами модуля объекта через
  `ЭтотОбъект`: в толстом клиенте он выполняется в том же процессе. Правишь движок управляемой формы - перенеси правку
  в `epf/ordinary-form/Module.bsl`. Управляемую форму из толстого клиента обычного приложения не открыть:
  `ОткрытьФорму` по имени - «Неизвестное имя формы», `ВнешниеОбработки.Подключить` не принимает ни адрес во временном
  хранилище, ни путь к файлу.
- `Form.bin` обычной формы - двоичный контейнер 1С, его собирает `python3 scripts/pack_ordinary_form.py` из
  `epf/ordinary-form/form.txt` (макет) и `epf/ordinary-form/Module.bsl`; тест проверяет, что `Form.bin` собран из
  текущих исходников. В макете - основной реквизит `ОбработкаОбъект` с идентификатором типа
  `ExternalDataProcessorObject.MCPLocalBridge` из `MCPLocalBridge.xml` (без него в модуле обычной формы нет ни
  `ЭтотОбъект`, ни свойств объекта), размер формы и назначенный обработчик `ПередОткрытием`. Остальные обработчики
  назначаются кодом (`УстановитьДействие`, `ПодключитьОбработчикОжидания`) и должны быть экспортными - это тоже
  проверяет тест. Переменные модуля не называть как свойства обычной формы (`Панель`, `Заголовок`, `Ширина`).
  Модальные окна (`Предупреждение`, `ДиалогВыбораФайла.Выбрать`) здесь допустимы, но на время показа стоит опрос.
- Буфер обмена (копирование идентификатора сеанса, `ПомещенВБуферОбмена` в обеих формах): `СредстваБуфераОбмена`
  есть с платформы 8.3.24 - обращение через `Вычислить`, иначе модуль не скомпилируется в режимах совместимости
  8.3.14 и 8.2; запасной путь - COM-объект `htmlfile` (Windows), последний - текст в окне сообщений.
- Режим совместимости 8.2: в модуле формы нет `ЭтотОбъект` - только `ЭтаФорма`. Возможности новее 8.2 (менеджер
  расширений, `ПолучитьИменаПредопределенных`) - через `Вычислить` или в отдельной `Попытке`, иначе модуль не
  скомпилируется или объекты индекса уйдут с ошибкой. Системных перечислений свойств метаданных
  (`ИспользованиеОбщегоРеквизита` и т. п.) в глобальном контексте нет ни на сервере, ни в толстом клиенте, хотя
  справка их описывает: значения - только через `Метаданные.СвойстваОбъектов` (обращение к свойству объекта
  компилируется везде, при отсутствии свойства - исключение при выполнении).
- Живой сеанс 1С через мост - это подключение к рабочей базе: команды шлются только с согласия пользователя.
