# Протокол обмена, версия 1

MCP-сервер и обработка `MCPLocalBridge` обмениваются файлами JSON в UTF-8 (обработка пишет с BOM, MCP - без
него; читать нужно с допуском BOM). Время везде - UTC в формате `ГГГГ-ММ-ДДTчч:мм:сс`.

## Каталоги

Корень по умолчанию - `%TEMP%\mcp-1c-local-bridge\` пользователя Windows (обработка берёт
`КаталогВременныхФайлов()`). На форме обработки можно выбрать другой корень: он хранится в настройках
пользователя 1С (`ХранилищеОбщихНастроек`, ключ объекта `MCPLocalBridge`, ключ настроек `КаталогОбмена`; пустая
строка - корень по умолчанию). MCP-серверу тот же корень задаётся переменной окружения `MCP_1C_BRIDGE_DIR`:
по протоколу стороны о корне не договариваются.

Каждая открытая форма обработки заводит свой каталог сеанса с новым идентификатором из 8 шестнадцатеричных
символов и удаляет его при закрытии формы. При смене корня на форме сеанс заводится заново, с новым
идентификатором, а прежний каталог сеанса удаляется. Корень может быть общим каталогом: MCP считает сеансами
только папки с таким именем и остальное содержимое корня не трогает.

```
<корень>\
  .clock                  проба часов: MCP пишет файл и берёт его время изменения как текущее время Windows
  <сеанс>\
    session.json          сведения о сеансе и сердцебиение (пишет обработка)
    in\<команда>.json     входящие команды (пишет MCP)
    work\<команда>.json   команда, взятая в работу (обработка переносит её из in)
    out\<команда>.json    ответ (пишет обработка)
```

Запись без промежуточных состояний: MCP пишет `in\<команда>.tmp` и переименовывает в `.json`, обработка так же
пишет ответ через `out\<команда>.tmp`. Обработка ищет только `*.json`.

## session.json

Обработка переписывает файл при открытии формы, раз в 2 секунды, перед командой и после неё.

| Поле | Значение |
| --- | --- |
| `protocol` | версия протокола, 1 |
| `bridgeVersion` | версия обработки |
| `session` | идентификатор сеанса моста (имя каталога) |
| `path` | каталог сеанса в Windows |
| `infobase` | `СтрокаСоединенияИнформационнойБазы()` |
| `user`, `userFullName` | имя и полное имя пользователя 1С |
| `sessionNumber` | номер сеанса информационной базы |
| `configuration`, `configurationSynonym`, `configurationVersion`, `compatibilityMode` | конфигурация |
| `platform`, `serverPlatform` | версия клиента и сервера 1С |
| `application` | `ordinary` - мост открыт обычной формой в толстом клиенте обычного приложения; управляемая форма поле не пишет |
| `started`, `heartbeat` | открытие формы и последнее сердцебиение |
| `state` | `ready`, `busy` (выполняет команду), `awaiting` (результат ждёт решения пользователя), `paused` (приостановлен на форме) |
| `busyCommand` | идентификатор выполняемой команды или команды, чей результат ждёт решения; иначе пустая строка |
| `progress` | ход долгой команды, которая выполняется порциями: `индекс метаданных: 45%`; иначе пустая строка. Обработка до версии 1.3.0 поле не пишет |
| `mode` | `auto` - ответы уходят сразу, `manual` - после решения пользователя |
| `allowWrite`, `allowClientCode` | разрешения «Запись в базу» и «Код на клиенте» |
| `commandsDone` | сколько команд выполнено |

Возраст сердцебиения MCP считает по времени изменения `session.json` и пробы `.clock` - оба ставит Windows,
поэтому расхождение часов MCP-сервера и Windows (бывает у виртуальной машины после сна) не мешает. Сеанс молчит дольше 10 секунд и не
занят командой - он не отвечает (форма закрыта без уборки, клиент упал или открыто модальное окно). Каталоги
сеансов, молчащих больше суток, MCP удаляет.

## Команда

```json
{"protocol": 1, "id": "20261021T101500123-a1b2", "type": "query", "ttlSec": 60, "text": "ВЫБРАТЬ 1", "rowLimit": 1000}
```

| Поле | Для каких команд | Значение |
| --- | --- | --- |
| `id` | все | идентификатор: момент создания UTC и случайный суффикс, поэтому порядок имён - порядок поступления |
| `type` | все | `ping`, `query`, `eval`, `execute`, `metadata`, `index` |
| `ttlSec` | все | срок, за который обработка должна начать команду, считая от времени изменения файла |
| `text`, `params`, `rowLimit` | `query` | текст запроса, параметры, предел строк каждого результата |
| `expression` | `eval` | выражение для `Вычислить()` |
| `code` | `execute` | код для `Выполнить()`; результат - переменная `Результат` |
| `side` | `eval`, `execute` | `server` или `client` |
| `allowWrite` | `eval`, `execute` | `true` - сохранить изменения; без разрешения «Запись в базу» на форме код выполняется с откатом и предупреждением |
| `transaction` | `eval`, `execute` | только для записи: `true` (по умолчанию, и если поля нет) - код в транзакции, которая фиксируется, только если он отработал без ошибок; `false` - без транзакции моста. Обработка до версии 1.3.0 поле не знает и пишет без транзакции |
| `path`, `filter` | `metadata` | полное имя объекта; отбор состава конфигурации |
| `refresh` | `index` | `true` - построить индекс метаданных заново, не беря сохранённый |

Обработка выполняет команды по одной в порядке имён. Перед выполнением она переносит файл в `work`; если
перенос не удался, команду уже снял MCP. Просроченную по `ttlSec` команду обработка не выполняет и отвечает
`expired`.

В режиме `manual` выполненная команда остаётся в `work`, а ответ - в памяти формы, пока пользователь не решит:
«Отдать агенту» пишет ответ как есть, «Не отдавать» - ответ `denied` без результата. До решения `state` -
`awaiting`, и следующие команды не начинаются. К решению пользователь может приложить комментарий агенту - он
уходит в поле `comment` того же ответа: с результатом или с `denied`.

MCP снимает команду сам, если она не начата за время ожидания вызова: удаляет её из `in`. Удалось - команда не
выполнится; файла уже нет - обработка её взяла, и вызов возвращает идентификатор для инструмента `result`.

## Ответ

```json
{"protocol": 1, "id": "20261021T101500123-a1b2", "status": "ok", "durationMs": 35, "result": {}, "messages": []}
```

| Поле | Значение |
| --- | --- |
| `status` | `ok`, `error` (исключение 1С), `rejected` (код на клиенте не разрешён на форме или неизвестная команда), `expired`, `denied` (пользователь не отдал результат) |
| `result` | результат для `ok` |
| `error`, `errorDetails` | описание ошибки и `ПодробноеПредставлениеОшибки()` |
| `messages` | сообщения пользователю, выданные на сервере во время команды |
| `rolledBack` | `true` - изменения серверного `eval`/`execute` откачены: проверочный прогон без записи или запись, которая не зафиксирована из-за ошибки |
| `transaction` | итог транзакции серверного `eval`/`execute`: `rolledBack` - откачена, `committed` - зафиксирована, `none` - транзакции моста не было (`transaction=false` или код сам её завершил), что код записал, сохранено. Обработка до версии 1.3.0 поле не пишет |
| `comment` | комментарий пользователя к решению в режиме `manual`, до 2000 символов; нет комментария - нет поля. Обработка до версии 1.2.0 поле не пишет |
| `warnings` | предупреждения: запись запрошена, но выполнена с откатом; код оставил незавершённую транзакцию или сам завершил транзакцию моста |
| `durationMs` | время выполнения на стороне обработки |

## Значения 1С в JSON

| Значение 1С | JSON |
| --- | --- |
| Строка, Число, Булево | как есть |
| Дата | строка `ГГГГ-ММ-ДДTчч:мм:сс` |
| Неопределено, NULL | `null` |
| УникальныйИдентификатор | строка |
| Ссылка | `{"_type": "<полное имя>", "_uuid": "...", "_presentation": "..."}` |
| Значение перечисления | `{"_type": "Перечисление.<Имя>", "_name": "<имя значения>", "_presentation": "..."}` |
| Массив, Структура, Соответствие со строковыми ключами | массив или объект |
| Соответствие с другими ключами | `{"_type": "Соответствие", "pairs": [{"key": ..., "value": ...}]}` |
| ТаблицаЗначений, результат запроса, набор записей регистра | `{"columns": [{"name", "types"}], "rows": [[...]], "total": N, "truncated": bool}` |
| ДеревоЗначений | то же, строки - `{"values": [...], "rows": [...]}` |
| СписокЗначений | `{"_type": "СписокЗначений", "items": [{"value", "presentation", "check"}]}` |
| Объект справочника, документа и т. п. | `{"_type": "<полное имя>.Объект", "isNew": bool, "fields": {...}}` с табличными частями |
| ОписаниеТипов | `{"_type": "ОписаниеТипов", "types": ["Строка(100)", "Справочник.Контрагенты"]}` |
| Тип, ОбъектМетаданных | строка: имя типа, полное имя объекта |
| ДвоичныеДанные | `{"_type": "ДвоичныеДанные", "size": N}` |
| прочее | `{"_type": "<тип>", "_presentation": "..."}` |

Вложенность ограничена 12 уровнями, строки таблиц и выборок - `rowLimit` (для `eval` и `execute` - 1000).
Ответ `query` - `{"results": [...]}` с результатом каждого запроса пакета; на месте `УНИЧТОЖИТЬ` - `null`.

## Индекс метаданных

Команда `index` отдаёт индекс метаданных сеанса: состав конфигурации с объектами активных расширений, поля
объектов с типами и связи между объектами. Код модулей в индекс не входит: из режима Предприятия тексты модулей
недоступны. Обработки до версии 1.3.0 команду не знают и отвечают `rejected`.

Обработка хранит индекс в настройках текущего пользователя этой информационной базы: `ХранилищеОбщихНастроек`,
ключ объекта `MCPLocalBridge`, ключ настроек `ИндексМетаданных`, текст JSON сжат в `ХранилищеЗначения`. Вместе
с индексом хранится отпечаток метаданных - SHA-1 от формата индекса, имени, версии и режима совместимости
конфигурации, имён, версий и хеш-сумм активных расширений, полных имён всех объектов и числа их полей
(реквизитов, полей табличных частей, измерений, ресурсов, значений перечислений). На каждую команду `index`
обработка считает отпечаток заново: совпал и `refresh` не `true` - отдаёт сохранённый индекс, иначе строит
новый и сохраняет его. Хеш-суммы основной конфигурации в режиме Предприятия нет, поэтому смену типа поля или
переименование без изменения числа полей отпечаток не замечает - для этого `refresh`.

Индекс строится порциями: за один опрос очереди сервер описывает объекты одной коллекции, пока не истечёт
бюджет в 1 секунду, и между порциями окно 1С отвечает пользователю. Пока идёт построение, команда остаётся в
`work`, `state` - `busy`, `busyCommand` - её идентификатор, `progress` - доля описанных объектов; следующие
команды ждут в `in`. Сохранить индекс в настройках может не получиться (нет права сохранять данные
пользователя) - тогда ответ всё равно приходит, с предупреждением в `warnings`.

Сам индекс в ответ не входит: обработка пишет его в файл `index.json` в каталоге сеанса (UTF-8 с BOM) и только
потом - файл ответа. В режиме `manual` файл пишется при выдаче ответа, при отказе его нет. Ответ:

```json
{"status": "ok", "result": {"file": "index.json", "source": "saved", "fingerprint": "...",
 "built": "2026-11-03T10:15:00", "objects": 15342, "fields": 61234}}
```

| Поле `result` | Значение |
| --- | --- |
| `file` | имя файла индекса в каталоге сеанса |
| `source` | `saved` - взят из настроек пользователя, `built` - построен этой командой |
| `fingerprint` | отпечаток метаданных, по которым построен индекс |
| `built` | момент построения индекса, UTC |
| `objects`, `fields` | сколько описаний объектов и полей в индексе |

Файл индекса - объект с полями `format` (1), `fingerprint`, `built`, `configuration` (`name`, `synonym`,
`version`, `compatibilityMode`), `extensions` (`name`, `version`, `hash`), `objects`, `fields` и `parts` -
порциями построения. Порция - `{"collection": "Справочники", "types": [...], "objects": [...]}`: в `types`
таблица типов порции, каждый тип - массив имён (`Строка(150)`, `Число(15,2)`, `Справочник.Контрагенты`);
поля ссылаются на тип номером в этой таблице, и составной тип, общий для многих полей, хранится один раз.
Определяемый тип в метаданных сеанса уже развёрнут в состав типов.

| Поле объекта | Значение |
| --- | --- |
| `full`, `name`, `synonym` | полное имя, имя, синоним (нет - совпадает с именем) |
| `extension`, `comment` | расширение, добавившее объект; комментарий |
| `error` | объект описать не удалось: текст ошибки, остальные поля могут отсутствовать |
| `type` | номер типа: константы, определяемые типы, параметры сеанса, ПВХ, общие реквизиты, критерии отбора |
| `attributes`, `dimensions`, `resources` | поля: `[имя, синоним, номер типа, расширение]`, синоним и расширение - пустые, если нет |
| `tables` | табличные части: `name`, `synonym`, `extension`, `attributes` |
| `values` | значения перечисления: `[имя, синоним]` |
| `predefined`, `forms`, `commands`, `templates` | имена предопределённых, форм, команд, макетов |
| `owners`, `basedOn`, `records` | владельцы справочника, ввод на основании, движения документа и последовательности (полные имена) |
| `content` | состав журнала, последовательности, подсистемы, критерия отбора, общего реквизита, функциональной опции |
| `exchangeContent` | состав плана обмена: `[полное имя, авторегистрация]` |
| `storage` | хранение функциональной опции |
| `chart`, `subconto`, `task` | план счетов или видов расчёта регистра, виды субконто плана счетов, задача бизнес-процесса |
| `periodicity`, `writeMode`, `registerKind` | периодичность и режим записи регистра сведений, вид регистра накопления |
| `flags`, `reuse` | признаки общего модуля (`Сервер`, `ВызовСервера`, `Глобальный`...), повторное использование |
| `method`, `isPredefined`, `use` | метод, предопределённость и использование регламентного задания |
| `source`, `event`, `handler` | подписка на событие: номер типа источника, событие, обработчик |
| `root`, `urlTemplates` | HTTP-сервис: корневой URL, шаблоны `[шаблон, [[HTTP-метод, обработчик]]]` |
| `namespace`, `operations` | Web-сервис: пространство имён, операции `[имя, процедура]` |

Вложенные подсистемы описываются отдельными объектами в той же порции, что и подсистема верхнего уровня.
